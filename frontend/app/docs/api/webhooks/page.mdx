# Webhooks API

Register HTTPS endpoints to receive real-time event notifications from Coal. When a payment is confirmed, an authorization is captured, or a session expires, Coal fires a signed POST request to your webhook URL.

This is a console-managed endpoint family. The public merchant API uses `x-api-key`; these `/api/console/*` routes use Privy Bearer tokens and are dashboard-only.

## The Webhook Object

```json
{
  "id": "clwh001",
  "merchantId": "clmerchant456",
  "url": "https://yoursite.com/api/webhooks/coal",
  "secret": "whsec_...",
  "events": ["checkout.confirmed", "checkout.failed"],
  "active": true,
  "createdAt": "2026-01-15T10:00:00.000Z"
}
```

| Field | Type | Description |
|---|---|---|
| `id` | string | Unique webhook ID (CUID) |
| `merchantId` | string | ID of the owning merchant |
| `url` | string | Your HTTPS endpoint that receives events |
| `secret` | string | Signing secret used to verify requests (`whsec_...`) |
| `events` | string[] | List of event types subscribed to |
| `active` | boolean | `false` = webhook is paused |
| `createdAt` | ISO 8601 | Creation timestamp |

---

## Event Types

| Event | Fired when |
|---|---|
| `checkout.confirmed` | Payment verified on-chain |
| `checkout.failed` | Transaction failed or was invalid |
| `checkout.expired` | Session timed out without payment |
| `checkout.authorized` | Auth & Capture — funds reserved |
| `checkout.voided` | Authorization released without capture |

Subscribe to `*` to receive all events.

---

## Event Payload Structure

Every webhook request is a `POST` with `Content-Type: application/json`:

```json
{
  "id": "evt_clxxx001",
  "event": "checkout.confirmed",
  "createdAt": "2026-03-22T12:03:41.000Z",
  "data": {
    "sessionId": "clxxx789",
    "amount": "49.99",
    "currency": "USDC",
    "status": "confirmed",
    "txHash": "0xdeadbeef...",
    "merchantId": "clmerchant456",
    "productId": "clxxx123",
    "confirmedAt": "2026-03-22T12:03:41.000Z"
  }
}
```

<Callout variant="info">
  Always use `event.id` to deduplicate — Coal may retry failed deliveries, and your handler may receive the same event more than once.
</Callout>

## Register a Webhook

<EndpointBadge method="POST" path="/api/console/webhooks" />

**Authentication:** `Authorization: Bearer <Privy JWT>`

<ParamTable params={[
  { name: "url", type: "string", required: true, description: "Your HTTPS endpoint. Must be publicly reachable and return 2xx within 10 seconds." },
  { name: "events", type: "string[]", required: true, description: "Array of event types to subscribe to. Pass [\"*\"] to receive all events." },
]} />

```bash
curl -X POST https://api.usecoal.xyz/api/console/webhooks \
  -H "Authorization: Bearer <Privy JWT>" \
  -H "Content-Type: application/json" \
  -d '{
    "url": "https://yoursite.com/api/webhooks/coal",
    "events": ["checkout.confirmed", "checkout.failed"]
  }'
```

```json
{
  "data": {
    "id": "clwh001",
    "url": "https://yoursite.com/api/webhooks/coal",
    "secret": "whsec_a1b2c3d4e5f6...",
    "events": ["checkout.confirmed", "checkout.failed"],
    "active": true
  }
}
```

<Callout variant="warning" title="Save your secret">
  The `secret` is shown only once at creation. Store it securely (e.g. in an environment variable) — you'll need it to verify incoming signatures.
</Callout>

## Verifying Signatures

Every request includes a `Coal-Signature` header. **Always verify it** before processing the event.

```
Coal-Signature: t=1711108821,v1=a8f3b2c1...
```

**Verification algorithm:**

1. Extract `t` (timestamp) and `v1` (signature) from the header
2. Build the signed payload string: `"{t}.{raw_body}"`
3. Compute `HMAC-SHA256(signed_payload, webhook_secret)`
4. Compare with `v1` using a timing-safe comparison

```typescript
// app/api/webhooks/coal/route.ts
import { NextResponse } from 'next/server';
import crypto from 'crypto';

export async function POST(req: Request) {
  const rawBody = await req.text();
  const sig = req.headers.get('Coal-Signature') ?? '';

  const parts = Object.fromEntries(sig.split(',').map((p) => p.split('=')));
  const { t, v1 } = parts;

  if (!t || !v1) {
    return NextResponse.json({ error: 'Missing signature' }, { status: 400 });
  }

  const signedPayload = `${t}.${rawBody}`;
  const expected = crypto
    .createHmac('sha256', process.env.COAL_WEBHOOK_SECRET!)
    .update(signedPayload)
    .digest('hex');

  if (!crypto.timingSafeEqual(Buffer.from(expected), Buffer.from(v1))) {
    return NextResponse.json({ error: 'Invalid signature' }, { status: 401 });
  }

  const event = JSON.parse(rawBody);

  switch (event.event) {
    case 'checkout.confirmed':
      await fulfillOrder(event.data.sessionId);
      break;
    case 'checkout.failed':
      await notifyCustomer(event.data.sessionId);
      break;
  }

  return NextResponse.json({ received: true });
}
```

See [Signature Verification](/docs/webhooks/signatures) for the full guide including timestamp tolerance and replay protection.

## Retry Behavior

Coal retries failed deliveries with exponential back-off:

| Attempt | Delay |
|---|---|
| 1st retry | 1 minute |
| 2nd retry | 5 minutes |
| 3rd retry | 30 minutes |
| 4th retry | 2 hours |
| 5th retry | 8 hours |

After 5 failed attempts, the event is marked `failed` and no further retries are made. See [Retry Logic](/docs/webhooks/retries) for how to replay missed events.

## Error Codes

| Code | HTTP | Description |
|---|---|---|
| `UNAUTHORIZED` | 401 | Missing or invalid Privy JWT |
| `NOT_FOUND` | 404 | Webhook does not exist or belongs to another merchant |
| `VALIDATION_ERROR` | 400 | Invalid URL or unknown event type |
| `URL_UNREACHABLE` | 422 | Coal could not reach the provided URL during registration |
